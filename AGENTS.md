# NOVACREST TECHNOLOGIES — AGENT GOVERNANCE

## 1. PROJECT IDENTITY

NovaCrest Technologies is a premium digital technology company delivering:

- Website development
- Mobile application development
- Custom software
- UI/UX and product design
- SEO
- Digital marketing
- Business technology solutions

The website must communicate:

**serious technology + exceptional design + human understanding + business impact.**

NovaCrest must never feel like:

- a developer portfolio
- a coding website
- an admin dashboard
- technical documentation
- a generic IT services company
- a SaaS landing page
- an AI-generated startup template
- a repetitive card-grid website
- a template assembled from UI components

The website should feel like a premium digital studio that happens to possess deep engineering capability.

---

# 3. THE CREATIVE NORTH STAR

The objective is NOT:

"make the existing website prettier."

The objective is:

**CREATE A DIGITAL EXPERIENCE THAT FEELS IMPOSSIBLE TO HAVE BEEN BUILT FROM A TEMPLATE.**

The visitor should feel:

### First 3 seconds
"Whoa. This is different."

### First 10 seconds
"These people build serious digital products."

### First 30 seconds
"They understand design, technology, and business."

### End of experience
"I want to talk to these people."

The site should create curiosity strong enough that the visitor wants to continue scrolling.

---

# 4. NEVER DEFAULT TO SAFE DESIGN

If an obvious implementation is:

- standard hero
- heading + paragraph + two buttons
- three cards
- logo strip
- services cards
- portfolio cards
- testimonials cards
- technology logos
- CTA card
- footer

do NOT automatically implement it.

Ask:

**What would make this section feel like an experience rather than a website section?**

Prefer:

- scenes
- chapters
- transitions
- spatial compositions
- visual storytelling
- interactive objects
- scroll choreography
- editorial layouts
- cinematic imagery
- product visualization
- visual metaphors
- controlled surprise
- meaningful motion

---

# 5. NO GENERIC DEVELOPER AESTHETIC

The following patterns are prohibited unless there is an exceptionally strong creative reason:

- excessive monospace typography
- terminal-style interfaces
- command-line graphics
- code snippets as decoration
- fake system statuses
- fake uptime numbers
- "SYSTEM ACTIVE"
- "99.99%"
- unnecessary version numbers
- fake architecture diagrams
- database-style interfaces
- browser-console aesthetics
- excessive grid lines
- neon cyan borders
- RGB gaming aesthetics
- excessive glowing outlines
- engineering dashboard cards
- specification-heavy visual blocks
- repetitive rectangular containers

Technology should feel sophisticated and desirable, not loudly technical.

---

# 6. FUNCTIONALITY MUST SURVIVE

Visual reinvention must NOT break existing business functionality.

Preserve:

- existing routes
- forms
- APIs
- integrations
- submissions
- validation
- navigation logic
- analytics
- SEO functionality
- dynamic content
- authentication
- backend communication
- existing business information
- existing useful components
- existing application behavior

Visual implementation may be rebuilt when necessary.

Do not preserve a weak visual structure merely because it already exists.

**Preserve behavior.
Reinvent experience.**

---

# 7. DO NOT PATCH A FUNDAMENTALLY BAD EXPERIENCE

If the current implementation is fundamentally generic:

STOP PATCHING IT.

Do not spend dozens of iterations changing:

- colors
- shadows
- radius
- spacing
- font sizes
- gradients

while keeping the same structural concept.

Instead:

1. identify the weak concept
2. reconceptualize the scene
3. establish a stronger composition
4. rebuild the visual implementation
5. preserve the underlying functionality

---

# 8. MOTION IS A CORE DESIGN SYSTEM

Motion is not decoration.

Motion should communicate:

- hierarchy
- cause and effect
- progression
- transformation
- continuity
- discovery
- emphasis
- physicality

Strong candidates include:

- scroll-linked animation
- pinned storytelling
- parallax
- image expansion
- scale transformation
- masked reveals
- clip-path transitions
- typography transformation
- text splitting
- horizontal scenes
- sticky visual stages
- 3D rotation
- object morphing
- image displacement
- cursor-reactive visuals
- magnetic controls
- video scrubbing
- color/environment transitions
- cross-section continuity

Avoid:

- random floating animations
- animation on every element
- endless fade-ins
- pointless bouncing
- excessive particle effects
- movement that does not communicate anything

---

# 9. EVERY MAJOR SECTION NEEDS A PURPOSE

For each major section, define:

### Narrative purpose
Why does this scene exist?

### Visual purpose
What should the visitor see?

### Interaction purpose
What can the visitor discover?

### Motion purpose
Why does anything move?

### Emotional purpose
What should the visitor feel?

### Conversion purpose
Why should the visitor continue?

If a section cannot answer these questions, reconsider the section.

---

# 10. MULTI-AGENT EXECUTION

Use specialized agents.

Do not make every agent independently rewrite the entire project.

Recommended roles:

### Creative Director
Defines the experience and makes final visual decisions.

### Experience / UX Architect
Defines the narrative, information architecture, and journey.

### Art Direction Agent
Defines composition, imagery, typography, color, materials, and visual language.

### Motion Designer
Defines scroll choreography, transitions, timing, easing, and interaction states.

### 3D / Visual Agent
Creates or engineers signature visual objects, 3D scenes, procedural visuals, Canvas/WebGL experiences, or visual alternatives.

### Frontend Architecture Agent
Ensures the experience can be implemented cleanly and maintainably.

### Hero + Navigation Agent
Builds the opening scene and global navigation behavior.

### Services Experience Agent
Turns service information into an immersive experience rather than generic service cards.

### Portfolio / Case Study Agent
Creates visual storytelling for work and projects.

### Brand Story Agent
Builds the human/company narrative.

### Technology Experience Agent
Communicates technical capability without becoming a stack dashboard.

### CTA + Footer Agent
Creates the closing emotional/conversion moment.

### Responsive Agent
Creates intentional mobile and tablet art direction.

### Accessibility Agent
Ensures inclusive interaction and reduced-motion behavior.

### Performance Agent
Protects performance while preserving visual ambition.

### SEO Agent
Ensures search visibility and semantic structure.

### Final Creative Director
Evaluates the complete site in a real browser.

---

# 11. AGENT DEPENDENCY RULE

Parallelize independent tasks.

Serialize tasks with shared-file dependencies.

### Safe early parallel work

These can generally work in parallel:

- experience exploration
- UX audit
- visual research
- copy audit
- asset research
- technical feasibility

### Foundation first

Before large-scale visual implementation:

- inspect project
- understand architecture
- inspect routes
- inspect data
- identify existing components
- identify shared styles
- establish design tokens
- establish layout architecture
- establish motion architecture

### Then parallelize section construction

Where safe:

- hero
- services
- portfolio
- brand story
- technology
- about/human section

### Final integration must be serialized

One integration pass must resolve:

- spacing conflicts
- typography inconsistencies
- animation conflicts
- responsive issues
- duplicated logic
- visual inconsistencies
- performance regressions
- accessibility regressions

---

# 12. FILE OWNERSHIP

Agents should avoid simultaneous editing of shared files.

Prefer:

- isolated components
- dedicated feature files
- shared tokens owned by one agent
- controlled integration
- explicit handoff

If multiple agents need to modify the same shared file:

DO NOT blindly merge conflicting edits.

Coordinate through the integration stage.

# 13. REQUIRED PLANNING ARTIFACTS

Before full implementation of a new creative direction, generate:

`EXPERIENCE-MAP.md`

`INTERACTION-MAP.md`

`IMPLEMENTATION-PLAN.md`

# 14. CREATIVE EXPLORATION

Before committing to a final direction:

Explore at least 3 radically different creative directions.

They should differ in:

- visual language
- composition
- storytelling
- motion
- hero concept
- signature visual object
- section transitions
- emotional tone

Do not present three minor color/style variations.

Select the strongest direction based on:

- memorability
- emotional impact
- originality
- NovaCrest relevance
- storytelling quality
- feasibility
- performance
- conversion potential

---

# 15. BROWSER-FIRST QA

Do not assume the implementation looks good because the code compiles.

Regularly inspect the actual rendered website in a browser.

Evaluate:

- composition
- alignment
- spacing
- hierarchy
- responsiveness
- interaction
- motion
- visual continuity
- typography
- image quality
- loading behavior
- hover behavior
- scroll behavior
- mobile behavior

Test the real experience rather than inspecting only source code.

---

# 16. THE "STOP SCROLLING" TEST

A strong section should make the visitor want to see what happens next.

Ask:

- Did this section surprise me?
- Does it create curiosity?
- Does something transform?
- Does the visual composition evolve?
- Is there an interaction worth discovering?
- Does the next section feel connected?
- Would I remember this section tomorrow?

If not, redesign it.

---

# 17. THE "IMPOSSIBLE WEBSITE" TEST

At every major review ask:

### Does this look like:
- a template?
- a generic SaaS site?
- an IT company?
- a developer portfolio?
- an AI-generated website?
- a collection of cards?

If yes:

**FAIL THE DESIGN.**

Reconceptualize.

---

# 18. THE 10-SECOND MEMORY TEST

The entire homepage must have at least one unmistakable visual memory.

For example:

- a signature transforming object
- cinematic scroll sequence
- unusual navigation
- product interface becoming part of the environment
- typography transforming into visual architecture
- interactive visual metaphor
- immersive transition between chapters
- distinctive spatial composition

The exact concept is for the Creative Director to determine.

But there MUST be a memorable signature.

---

# 19. COPY RULES

Copy should be:

- human
- concise
- confident
- intelligent
- specific
- conversational when appropriate
- visually integrated

Avoid empty technology buzzwords such as:

- cutting-edge
- innovative solutions
- next-generation
- seamless solutions
- leveraging technology
- end-to-end digital solutions
- transformative digital experiences

Do not manufacture claims.

---

# 20. VISUAL SYSTEM

The site must have a coherent visual system.

However:

**consistency does not mean repetition.**

Use a shared language for:

- typography
- spacing
- colors
- interaction behavior
- image treatment
- borders
- radii
- shadows
- transitions
- buttons
- navigation

But individual sections can have different compositions.

The website should feel like one world containing many scenes.

---

# 21. RESPONSIVE DESIGN

Do not simply shrink desktop.

Mobile may require:

- different composition
- different animation
- different interaction
- simplified 3D
- alternate visual sequence
- changed typography scale
- different navigation
- altered section ordering

Mobile must remain premium.

---

# 22. ACCESSIBILITY

Preserve accessibility.

Required considerations:

- keyboard navigation
- focus visibility
- semantic HTML
- sufficient contrast
- descriptive labels
- accessible forms
- screen-reader support
- reduced-motion support
- accessible interactive controls

Motion must never prevent users from using the website.

---

# 23. PERFORMANCE

Creative ambition must not become careless engineering.

Use:

- lazy loading
- responsive images
- modern image formats
- optimized video
- poster images
- GPU-conscious animation
- code splitting where useful
- progressive enhancement
- reduced-motion fallbacks
- efficient event listeners
- cleanup of animation contexts

Do not load heavy 3D or video merely because it looks impressive.

Choose technology based on actual experience requirements.

---

# 24. SEO

Preserve and improve:

- semantic HTML
- heading hierarchy
- metadata
- page titles
- descriptions
- Open Graph
- structured data where appropriate
- crawlability
- internal linking
- image alt text
- performance
- indexable content
- meaningful page content

Visual experimentation must not damage discoverability.

---

# 25. DECISION RULE

When choosing between:

### Option A
Easy, familiar, predictable, template-like

and

### Option B
More original, more art-directed, more memorable, but technically thoughtful

Prefer Option B when it remains:

- usable
- accessible
- performant
- maintainable
- relevant to NovaCrest

---

# 26. AUTONOMOUS EXECUTION

Do not repeatedly ask the user to manually coordinate:

- which agent should work next
- which file should be edited
- which component should be built
- whether to continue to the next phase

Use the documented workflow.

Pause only when:

- a genuine business decision is required
- information is missing that cannot be inferred safely
- implementation could destroy existing functionality
- two genuinely conflicting requirements cannot be resolved

Otherwise continue autonomously.

---

# 27. FINAL CREATIVE DIRECTOR REVIEW

Before considering the project complete, evaluate the entire experience as one piece.

Check:

### Visual
Is it unmistakably NovaCrest?

### Emotional
Does it create curiosity and desire to continue?

### Interaction
Does the user discover things rather than simply scroll past them?

### Motion
Does motion communicate rather than decorate?

### Composition
Does it feel art-directed rather than assembled?

### Originality
Could this be mistaken for a template?

### Conversion
Does the visitor understand why they should contact NovaCrest?

### Mobile
Does the experience remain exceptional?

### Performance
Does it remain fast enough to be usable?

### Accessibility
Can diverse users operate it?

### SEO
Can search engines understand it?

### Final question

**Would this website make a visitor stop, explore, remember it, and tell someone about it?**

If the answer is no:

DO NOT DECLARE THE PROJECT FINISHED.

Rework the weakest experience.
